# Pulse Web: как появился новый фронт (итоги 24.09.2026)

Краткая история перехода на Pulse v2 для тех, кто придёт в проект позже. Подробности — в документах по ссылкам.

## Что поменялось в концепции

Было: один общий пул комплиментов, одна глобальная рассылка всем подписчикам, отдельная админка по API-ключу.

Стало:
- **Автор** регистрируется (Keycloak), ведёт свои комплименты, создаёт одноразовую ссылку-приглашение и видит своих подписчиков.
- **Получатель** открывает ссылку `/s/<код>` и подписывается на push-уведомления **без регистрации и входа, только по коду**. Это главное требование.
- PulseApp.Admin больше не нужен: работа с комплиментами и список подписок перенесены в кабинет автора.

## Ключевые решения

- Одно SPA: React 19 + TypeScript (strict) + Vite + React Router 7.
- Публичная часть (`/`, `/s/:code`) и кабинет (`/app/*`, `/auth/*`) — разные lazy-чанки. Код входа (`oidc-client-ts`, `react-oidc-context`) и TanStack Query попадают только в чанки кабинета.
- Запрет на авторизацию в пути получателя проверяет ESLint (`no-restricted-imports` в `eslint.config.js`). Запросы получателя идут через `shared/api/publicApi.ts` без `Authorization`.
- Модель данных — как в текущем бэкенде: общий пул комплиментов на автора, безымянные одноразовые ссылки на 24 часа.
- Кабинет автора — **сначала десктоп** (боковая навигация, таблицы, модалки). Страница подписки и лендинг — сначала телефон.
- Вход: страница Keycloak, Authorization Code + PKCE. Регистрация — `prompt=create`.
- Одно устройство подписано на одного автора: `Endpoint` на бэкенде уникален. Фронт помнит подписку в `localStorage` (`pulse.subscription`) и перед подпиской пересоздаёт браузерную подписку, чтобы endpoint был новым.
- Service worker только показывает push. Кэширование запросов убрано; формат payload прежний, старые подписчики продолжают получать уведомления.

## Как шла работа

1. Изучили старые Frontend, Admin и бэкенд. Нашли, что бэкенд уже переходит на Keycloak и коды приглашений, а старые фронты с ним не работают.
2. Brainstorming → спецификация → план. Замечания по бэкенду вынесли в отдельный документ.
3. Спайк на iPhone (сохранится ли код ссылки после «На экран „Домой“») **пропустили** по решению владельца: push на iPhone уже проверен на старом фронте. Поэтому не сделаны задача 10 (манифест со `start_url` ссылки) и вариант с манифестом через nginx. Страховка — поле «Вставьте ссылку или код приглашения» на главной в установленном приложении.
4. Реализация по TDD, задача за задачей. Каждая задача — отдельный коммит в ветке `feature/web-v2`.
5. Независимое ревью всей ветки. Найдены и исправлены два бага входа (тестами с настоящим `AuthProvider`):
   - после входа автор не возвращался на страницу, с которой ушёл в Keycloak;
   - сбой фонового обновления токена закрывал кабинет экраном ошибки.
6. Локальный запуск: исправлен dev-сервер (см. «Подводные камни»).

Итог: 32 тестовых файла, 206 тестов, линтер и сборка зелёные.

## Подводные камни (пригодится при следующем запуске)

- **Node 25+ и тесты.** Node объявляет собственный `localStorage` и перекрывает jsdom. В `vite.config.ts` тестовым процессам передаётся `--no-experimental-webstorage`.
- **Windows и `localhost`.** Node разрешает `localhost` в `::1`, Vite слушал только IPv6, браузер получал `ERR_CONNECTION_REFUSED`. Теперь dev-сервер слушает `127.0.0.1`, а запросы на `127.0.0.1` перенаправляет на `localhost`: redirect URI в Keycloak прописан только для `http://localhost:5173`, с другим origin вход падает с «Invalid parameter: redirect_uri».
- **Песочница Claude Code** не пускает соединения на localhost, поэтому ручные проверки в браузере делает человек по чек-листу из README.
- **React Router data-роутер в jsdom.** При навигации `Request` из Node не принимает `AbortSignal` из jsdom. В `src/features/auth/authFlow.test.tsx` `Request` подменён только для этого файла.

## Что ещё не работает до правок бэкенда

Подробно — в `backend-notes-web-v2.md`:
- **A1.** `[HttpPost("/create")]` → `[HttpPost("create")]`, иначе «Создать ссылку» не работает.
- **A2.** Фильтрация комплиментов по автору (сейчас видны и редактируются чужие).
- **A3.** Нет `GET /api/subscription` — страница «Подписчики» показывает ошибку.
- **A4.** Рассылка должна слать каждому подписчику комплименты его автора.
- Keycloak на проде: клиент `pulse-web`, аудитория токена, переменные `OIDC_AUTHORITY` и `OIDC_CLIENT_ID` для контейнера.

## Отложено

- Проверить на iPhone, где открывается установленное приложение: на странице ссылки или на главной. Если на главной — сделать задачу 10 из плана.
- Мелочи из ревью:
  - «Повторить» в ошибке всегда подписывает заново, даже после неудачной отписки;
  - нет `.catch`, если запрос разрешения завершится ошибкой (зависнет «Минутку…»);
  - «Отписаться» на лендинге без защиты от двойного нажатия;
  - счётчик `N/500` не закреплён тестом;
  - нет теста на `\r\n` вместе со слишком длинной строкой в импорте;
  - модалка закрывается по Esc без подтверждения;
  - `index.html` без `Cache-Control: no-cache`;
  - ошибки `application/problem+json` показываются сырым JSON.
- Решение по ветке `feature/web-v2`: влить в `dev` (push в `dev` запускает CI и выкладку) или открыть Pull Request.
