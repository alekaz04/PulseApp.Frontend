# Отправка комплимента со страницы «Комплименты» и имя подписчика

> Спецификация, 26.09.2026. Репозиторий: `PulseApp.Frontend`.
> Бэкенд сверен с `PulseApp.Backend` на коммите `680433d`. Правки бэкенда в эту работу не входят (см. раздел 7).

## 1. Цель

1. В окне отправки одного комплимента уже отправленные комплименты (`isBeenPushed: true`) видны, но выбрать их нельзя.
2. Отправка одного комплимента переезжает со страницы «Подписчики» на страницу «Комплименты».
3. Фронт работает с новым API бэкенда: у подписчика есть имя, код приглашения создаётся с именем, отправка одного комплимента идёт по новому адресу.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Объём работ | Только фронт. Фронт пишется под ожидаемый контракт (раздел 3), даже если бэкенд его ещё не выполняет |
| Отправленные комплименты в окне | Серые, недоступны для выбора (`disabled`), с меткой «Отправлен», стоят в конце списка. Чтобы отправить повторно, комплимент возвращают в очередь |
| Где запускается отправка | Кнопка «Отправить» в шапке страницы «Комплименты». Получатель выбирается в окне |
| Где живёт код окна | `features/compliments/`. Окно само загружает подписчиков через `useSubscriptions` из `features/subscribers/queries.ts`. Отдельную фичу `features/send/` не заводим: у окна один потребитель |
| Имя получателя при создании ссылки | Обязательное, пробелы по краям обрезаются, не длиннее 100 символов (в символах, как `charCount`) |

## 3. Контракт API

| Действие | Запрос | Ответ |
|---|---|---|
| Отправить один комплимент | `POST /api/compliment/push/to/{subscriptionId}?complimentId={id}` | `200`, пустое тело. Бэкенд ставит комплименту `IsBeenPushed = true` |
| Создать код приглашения | `POST /api/code/create`, тело `{ "name": string }` | Код строкой (JSON-строка или `text/plain`). Пустое или отсутствующее `name` → `400` |
| Список подписчиков | `GET /api/subscription` | `[{ id, name, userAgent, createdAt, isActive }]` |

Было: `POST /api/subscription/push/to/{id}` и `POST /api/subscription/create` без тела.

Типы на фронте:

- `MySubscriptionDto` получает поле `name?: string | null`. Поле необязательное: бэкенд его пока не отдаёт, у старых подписок имени нет.
- `authedApi.createInviteCode(name: string): Promise<string>` шлёт `{ name }` на `/api/code/create`. Проверка пустого ответа остаётся.
- `authedApi.sendCompliment` уже переведён на новый адрес в рабочей копии (не закоммичено). Эта правка входит в первый коммит работы.

## 4. Экраны

### 4.1. «Ссылка» (`/app/invite`)

- Над кнопкой появляется поле «Имя получателя» (`Field` + `TextInput`) со счётчиком `n/100`.
- При нажатии «Создать ссылку» поле проверяется: пустое → «Введите имя», длиннее 100 символов → «Не больше 100 символов». С ошибкой запрос не уходит.
- В запрос уходит имя без пробелов по краям.
- После создания ссылки поле сохраняет значение. Для следующей ссылки автор вводит новое имя и снова нажимает кнопку.
- Остальное без изменений: копирование, «Поделиться», подсказка про одноразовую ссылку.

### 4.2. «Подписчики» (`/app/subscribers`)

- Колонки: «Имя», «Устройство», «Подписан», «Статус».
- Имя без пробелов по краям. Если имени нет или оно пустое, в ячейке «—».
- Кнопки «Отправить комплимент», колонки действий, окна отправки и мутации на странице больше нет.
- Сортировка прежняя: активные сверху, внутри группы новые сверху.

### 4.3. «Комплименты» (`/app/compliments`)

Шапка: **[Отправить]** (secondary) **[Добавить списком]** (secondary) **[Добавить]** (primary). Кнопка «Отправить» видна всегда.

Окно «Отправить комплимент»:

**Получатель.** Нативный `<select>` в `Field` с подписью «Получатель».
- Варианты — только активные подписки в порядке `sortSubscriptions`.
- Подпись варианта: `«Маша · iPhone · Safari»`, то есть имя и `parseUserAgent(userAgent)`. Без имени — только устройство.
- Под полем подсказка «Уведомление придёт сразу.» (перенесена из прежнего окна).
- Если активная подписка одна, она выбрана сразу. Иначе первым идёт пустой вариант «Выберите получателя».
- Нет активных подписок → пустое состояние «Нет активных подписчиков» с кнопкой-ссылкой «Создать ссылку» на `/app/invite`. Список комплиментов при этом не показывается.
- Если после перечитывания выбранный получатель пропал из активных, выбор сбрасывается. Выбор хранится как id; валидным считается только id из текущего списка активных.

**Комплимент.** Радиогруппа «Комплимент», как сейчас.
- Порядок: сначала неотправленные, затем отправленные; внутри группы новые сверху.
- Отправленные: радиокнопка `disabled`, строка приглушена, метка «Отправлен».
- Все комплименты отправлены → над списком подсказка «Все комплименты уже отправлены. Чтобы отправить повторно, верните комплимент в очередь.»
- Нет комплиментов → пустое состояние «Пока нет комплиментов» (без кнопки-ссылки: автор уже на странице комплиментов).

**Состояния загрузки.** Пока грузятся подписки или комплименты — спиннер. Ошибка любой загрузки — `ErrorState` с повтором именно этого запроса.

**Кнопки.** «Отмена» и «Отправить». «Отправить» доступна, когда выбраны и получатель, и комплимент и запрос не выполняется. Во время запроса текст «Отправляем…».

**После отправки.**
- Успех → тост «Комплимент отправлен», окно закрывается.
- Ошибка → тост с сообщением и traceId, окно остаётся открытым.
- При любом исходе перечитываются `['compliments']` (бэкенд меняет `IsBeenPushed`) и `['subscriptions']` (бэкенд отключает подписку, если push-сервис ответил 404/410).

## 7. Известные проблемы бэкенда (вне рамок)

На коммите `680433d` бэкенд не выполняет контракт из раздела 3:

1. `SubscriptionCodeController` без конструктора: `_handler` равен `null`, `POST /api/code/create` падает с `NullReferenceException` (500).
2. В `SubscriptionDto` нет `Name`, поэтому `GET /api/subscription` имя не отдаёт.
3. `SubscriptionService.CreateOrUpdateSubscription` не переносит `SubscriptionCode.Name` в `Subscription.Name`.
4. Нет миграции для колонок `Name` в таблицах подписок и кодов. Длину стоит ограничить 100 символами, как на фронте.

Пока это не исправлено, создание ссылки на странице «Ссылка» заканчивается ошибкой, а в списках вместо имён показываются «—» и устройство.

## 8. Вне рамок

Правки бэкенда, переименование подписчика, отправка одного комплимента нескольким получателям, отправка из строки таблицы комплиментов, повторная отправка без возврата в очередь.
